# Power Platform solution workspace

This folder contains the executable bootstrap and build specification for the real Power Platform Performance Lab.

## Target solution

- Solution unique name: `PowerPlatformPerformanceLab`
- Publisher unique name: `ppplperformancepublisher`
- Publisher prefix: `pppl`
- Ownership model for benchmark tables: organization-owned
- Data policy: synthetic data only

## Automated components

The bootstrap script creates an unmanaged Dataverse solution and two generic tables:

- `pppl_benchmarkrecord`
- `pppl_benchmarkrun`

It also creates the columns required by the initial benchmark catalog and publishes the customizations.

The seed script creates deterministic synthetic records with Dataverse `CreateMultiple` so the same workload can be reproduced without importing customer data.

The validation script verifies that the expected solution, tables, and columns exist.

## Canvas App

The Canvas benchmark runner must be created and published through supported Power Apps tooling. The current `.pa.yaml` source format is generated by Power Apps and should not be fabricated as an unvalidated application.

Use [canvas/BUILD_SPEC.md](canvas/BUILD_SPEC.md) as the implementation specification.

After the app exists in the development environment:

1. add it to `PowerPlatformPerformanceLab`;
2. publish it;
3. use Power Platform Git Integration for Canvas source control;
4. export/unpack the solution for ALM validation.

## CI/CD

`.github/workflows/bootstrap-power-platform-lab.yml` can authenticate with GitHub OIDC/Federated Identity, provision the solution metadata, optionally seed data, validate it, export the solution, and upload the exported/unpacked solution as a workflow artifact.

No client secret is required when OIDC/FIC is configured.
